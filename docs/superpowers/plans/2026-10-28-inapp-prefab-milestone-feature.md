# In-app Prefab — Milestone Feature Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `kinoa-inapp-template-to-prefab` renders milestone in-apps (one in-app instance, continuous progression) as a horizontally scrolling ladder of steps. Each step shows its score, reward and status. A step is collected either by its own button, or by one shared CTA that takes over the CTA of the step that is ready. A collect-all button is wired when the template has one.

**Architecture:** The planner picks a **CTA mode** for milestone templates:
- `per_step` (the default): each step has its own collect button.
- `single`: there is no per-step button; the template's one CTA slot, or the feature's main button, carries the ready step's CTA.

The planner also detects a collect-all slot. It records the decisions in a new `plan.milestone` block and emits scroll nodes (`ScrollRect` → viewport → content → step template) in place of the bar and markers for **new** plans.

The view routes every milestone button through one click resolver:
- close → close;
- free collect → `CollectMilestonesAsync`;
- paid, ad or link → a game-supplied `KinoaInAppFeatureHooks.RunButtonAction`, then collect.

Everything is **additive**: new plan fields, new builder cases, and two new shared files. No existing user-owned file gains a member, old plans still build, and standard and mission templates keep today's output.

**Tech Stack:** Python 3 stdlib (planner/codegen, `unittest`), generated C# for Unity 2022.3 uGUI (+ optional TMP), Kinoa Unity SDK (`Kinoa.Messaging`, `InAppMilestonesFeature`).

## Global Constraints

- **Backward compatibility is mandatory: extend, never rewrite.** A game project generated by the current release must keep compiling after a new `generate`, with no manual edit:
  - `render_hooks` (`Shared/KinoaInAppHooks.cs`) and `render_item_view` (`Shared/KinoaInAppItemView.cs`) stay **byte-identical**. Their public members never change.
  - New delegates live in the new `Shared/KinoaInAppFeatureHooks.cs`.
  - The Editor builder keeps **every** existing component, binding and field-type case, so an existing `*.inapp-plan.json` with the bar and markers still builds.
  - The old milestone node and field names (`MilestoneBar`, `MilestoneFill`, `MilestoneMarkers`, `MilestoneMarker`, `milestoneBarRoot`, `milestoneFill`, `milestoneMarkersRoot`, `milestoneMarkerTemplate`) stay in `RESERVED_NODE_NAMES` / `RESERVED_FIELDS`.
  - New `PlanNode` fields default to false when absent from old JSON.
- Python helpers stay **stdlib-only, no sibling imports**. Tests are offline: `python -m unittest discover tests` from the repo root.
- Generated C# never contains any `FORBIDDEN_IN_GENERATED` string (`dashboard.kinoa.io`, `Bearer`, `UnityWebRequest`, `Addressables.Load`). The skill **never writes an IAP, ad, image-download or deep-link method**: it calls a delegate the game assigns, or leaves `TODO(kinoa-prefab)`.
- SDK contract (verified in `E:\Dev\kinoa-sdk\KinoaSDK\KinoaCore`):
  - Collect call: `Kinoa.Messaging.CollectMilestonesAsync(InAppMessage, List<uint>)` with **0-based** step indexes. It returns `InAppMilestonesCollectResult { Collected, NotCollected, InApp }`.
  - A non-null `InApp` means the instance was reset (final claim on a capped in-app). Bind it.
  - Otherwise call `Message.SetMilestonesStatusAsCollected(response.Data.Collected)`.
  - Rewards come from `Steps[index].Button.Resources`.
  - Data shapes: `InAppMilestoneStatus` is `Unknown, Closed, Reached, Collected`. `InAppMilestonesFeature` has `Progress`, `PreviousProgress`, `ActiveProgressButton` and `Steps`. `Progress` is cumulative.
- Click config classes are all in `Kinoa.Data.Messaging.InApp`:
  - `InAppCloseClickConfiguration`
  - `InAppCollectResourceClickConfiguration`
  - `InAppPromiseRewardsClickConfiguration`
  - `InAppBillingClickConfiguration`, `InAppSoftBillingClickConfiguration`, `InAppShowAdClickConfiguration`, `InAppDeepLinkClickConfiguration`, `InAppWebLinkClickConfiguration`, …
- Milestone menus accept nine click actions, never `custom`.
- File ownership:
  - The Editor builder is tool-owned and rewritten by every `generate`.
  - `Shared/*.cs` files are **user-owned** and written only when absent, unless `--force-shared`. The new `Shared/KinoaInAppMilestoneStepView.cs` and `Shared/KinoaInAppFeatureHooks.cs` join that set.
- "Other prefab rules should be the same as it is now for regular inapps." Slot binding, de-overlap, canvas, facade routing of template slots, customs, client zones and events are unchanged. A standard or mission plan's view contains no milestone code.

    ```

     "cta_mode_source": "override" | "template_cta_count" | "default",
     "cta_slots": [<button keys counted as CTAs>],
     "single_cta": None | {"key": str | None, "button_field": str, "label_field": str},
     "collect_all": None | {"key": str, "button_field": str, "label_field": str, "can_be_hidden": bool}}
    ```
  - `report["milestone"] = {"cta_mode", "cta_mode_source", "collect_all": <key or None>}`
  - The `plan_prefab` option `"milestone_cta"` takes `"auto"` (default), `"per_step"` or `"single"`. The CLI `plan --milestone-cta {auto,per_step,single}` uses default `auto`.

Rules:
- **Collect-all slot.** It is the first button, by `index`, whose `key` or `name` matches `_COLLECT_ALL_RE`. If several match, add a warning.
- **CTA slot.** A button is a CTA when it is not the collect-all slot, and either:
  - `set(clickActionType) - {"close"}` is non-empty, or
  - its `clickActionType` is empty and its key does not match `close|dismiss`.

  When the layout has elements, only keys in `placed_keys` (they have a bbox) count. That is "on the tip image".
- **Mode.**
  - `override` in (`per_step`, `single`) → that mode, with source `override`.
  - Else, exactly one CTA slot → `single`, with source `template_cta_count`.
  - Else → `per_step`, with source `default`.
- **`single_cta`.** In `single` mode with exactly one CTA slot it is that slot's fields. In `single` mode otherwise it is `{"key": None, "button_field": "milestoneMainButton", "label_field": "milestoneMainButtonLabel"}`. With an override and two or more CTA slots, also add the warning `"--milestone-cta single with N CTA slots: the step CTA goes onto MilestoneMainButton"`. In `per_step` mode it is `None`.

  - `private static float StepProgress(decimal progress, long previous, long score)` returns `Clamp01((progress - previous) / (score - previous))` when `score > previous`, else `progress >= score ? 1f : 0f`.
  - `private string StepLabel(InAppCustomButton button)` returns `ResolveButtonLabel(button)`, or `"Collect"` when that is empty or `button` is null.

  - `private void OnFeatureButtonClicked(string clickKey, InAppCustomButton slot, List<uint> indexes)` does this, in order:
    1. If `_collecting`, return.
    2. Send `SendInAppClickEvent` and `ButtonClicked?.Invoke(this, clickKey, slot?.ClickConfig)`.
    3. Close config → `Close()`.
    4. A free config (`config == null || config is InAppCollectResourceClickConfiguration || config is InAppPromiseRewardsClickConfiguration`) → `_ = CollectStepsAsync(indexes)` when `indexes.Count > 0`.
    5. Otherwise → `_ = RunActionThenCollectAsync(slot, indexes)`.
  - `private async Task RunActionThenCollectAsync(InAppCustomButton slot, List<uint> indexes)`:
    - When `KinoaInAppFeatureHooks.RunButtonAction == null`: `KinoaInAppFeatureHooks.WarnMissing(nameof(KinoaInAppFeatureHooks.RunButtonAction)); return;`. **No collect.**
    - Otherwise it awaits the hook, in try/catch; on an exception it warns and does not collect.
    - It returns if `this == null`.
    - It collects only when the hook returned true and `indexes.Count > 0`.
  - `private async Task CollectStepsAsync(List<uint> indexes)`:
    - It sets `_collecting = true`, then runs `try { … } finally { _collecting = false; }`.

    - On failure: `Debug.LogWarning(... response?.Error?.Message ...)`, then `Bind(Message)`.
    - On success, `foreach (var index in response.Data.Collected)` carries the comment `// TODO(kinoa-prefab) apply steps[(int)index].Button.Resources to the player's economy here (same place as KinoaUiService.GrantRewards).`
    - Then `Bind(response.Data.InApp)` when it is non-null. Otherwise `Message.SetMilestonesStatusAsCollected(response.Data.Collected)`, then `Bind(Message)`.
  - `BindFeature` body:
    1. `milestoneScroll.gameObject.SetActive(feature != null)`. If `feature == null`, return.
    2. `var steps = feature.Steps ?? new List<InAppMilestoneStep>();` and `var reached` lists the `uint` indexes whose status is `Reached`.
    3. For each step, spawn an item and call `SetScore(step.Score.ToString())`, `SetReward(...)`, `SetProgress(StepProgress(feature.Progress, previous, step.Score))` and `SetStatus(step.Status)`. The reward is the first resource's icon via `ResolveIcon`, with the amount as `Amount.ToString()` for one resource or `$"x{count}"` for several, as in `BindGrandPrize`.
       - `per_step`: `item.SetCollect(step.Status != InAppMilestoneStatus.Collected, step.Status == InAppMilestoneStatus.Reached, StepLabel(step.Button), () => OnFeatureButtonClicked("milestone_step_" + i, step.Button, new List<uint> { index }))`, with loop locals captured. After the loop: `ApplyFeatureButton(milestoneMainButton, milestoneMainButtonLabel, feature.ActiveProgressButton, "milestone_main", reached, canBeHidden: true);`
       - `single`: `item.SetCollect(false, false, null, null);`. After the loop: `BindSingleCta(feature, steps, reached)` on the `single_cta` fields:
         - When `reached.Count > 0`: `ApplyFeatureButton(btn, lbl, steps[(int)reached[0]].Button, "milestone_step_" + reached[0], new List<uint> { reached[0] }, canBeHidden: false)`.
         - Otherwise, when `feature.ActiveProgressButton != null`: `ApplyFeatureButton(btn, lbl, feature.ActiveProgressButton, "milestone_main", new List<uint>(), canBeHidden: false)`.
         - Otherwise: a template slot (key non-None) keeps its `BindButtons` binding; for the main button (key None), call `btn.gameObject.SetActive(false)`.
    4. Collect-all, only when `plan["milestone"]["collect_all"]` is set: `InAppCustomButton collectAllSlot = null; Data.Buttons?.TryGetValue("<key>", out collectAllSlot); ApplyFeatureButton(<button_field>, <label_field>, collectAllSlot, "<key>", reached, canBeHidden: <can_be_hidden>); if (<button_field> != null) <button_field>.interactable = reached.Count > 0;`
    5. `FocusStep(...)`, then `BindGrandPrize(steps)` (unchanged).
